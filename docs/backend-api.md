# 백엔드에 필요한 API (P3 추가 기능)

실제 API 서버는 이 저장소 밖에 있습니다. 데모 모드는 목업 어댑터(`src/mocks/adapter.ts`)가 아래 API를 대신 응답하며, 실제 서버도 같은 계약으로 만들어야 화면이 그대로 동작합니다.

- 응답 형식은 기존 API와 같습니다: `{ code: "00", msg, data }`. 실패는 `code`가 `"00"`이 아니고 `msg`에 사용자에게 보여 줄 문구를 담습니다.
- 관리자 API는 관리자 서버(`NEXT_PUBLIC_ADMIN_URI`)로, 토큰은 기존과 같이 `Authorization: Bearer` 헤더로 보냅니다.
- 날짜는 요청에서 `YYYYMMDD`, 응답에서 `YYYY-MM-DD`(일시는 `YYYY-MM-DD HH:mm:ss`)입니다.

## 일괄 배정 (v2.4.0)

`PATCH /api/admin/match/bulk` — 배정관리 미배정 목록에서 고른 의뢰들에 법무대리인 한 명을 한 번에 지정합니다.

요청 본문(JSON)

| 필드 | 타입 | 설명 |
|---|---|---|
| `rqstNoList` | `string[]` | 의뢰번호 목록 (화면은 한 페이지 안에서 고르므로 최대 100건) |
| `lgagMembNo` | `string` | 법무대리인 회원번호 (`GET /api/admin/match/members/10`의 `membNo`) |

응답 `data`

| 필드 | 타입 | 설명 |
|---|---|---|
| `successList` | `string[]` | 배정완료로 바뀐 의뢰번호 |
| `failList` | `{ rqstNo: string; reason: string }[]` | 배정하지 못한 의뢰와 사유 (화면에 그대로 표시) |

서버가 지켜야 할 규칙

- 건마다 따로 처리하고, 일부가 실패해도 나머지는 배정합니다(부분 성공). 전체를 되돌리지 않습니다.
- 단건 배정(`PATCH /api/admin/match`)과 같은 검증을 합니다. 미배정 상태(등기의뢰·보완필요)가 아니면 실패("이미 배정완료 상태입니다."), 배정 정보(채무자·담보목적물 주소·채권최고액·설정약정일·등기고유번호)가 빠졌으면 실패(빠진 항목과 "배정 화면에서 입력해 주세요.")로 돌려줍니다.
- 법무대리인이 없거나 없는 회원이면 전체를 처리하지 않고 `code`를 실패로 돌려줍니다.
- 배정한 건은 진행 이력(감사 기록)에 처리자·시각과 함께 "일괄 배정"으로 남깁니다.
- 법무대리인에게 보내는 전달사항은 받지 않습니다(건마다 다르므로 단건 배정 화면에서).

## 감사 기록 (v2.5.0)

`GET /api/admin/audit/list` — 누가 언제 어떤 의뢰를 어떻게 바꿨는지 최근 순으로 돌려줍니다.

쿼리

| 이름 | 설명 |
|---|---|
| `fromDate`, `toDate` | 처리일 범위(`YYYYMMDD`, 양 끝 포함). 비면 제한 없음 |
| `searchRqstNo` | 의뢰번호(포함 검색) |
| `searchMembNm` | 처리자 이름(포함 검색) |
| `pageNum`, `pageSize` | 쪽 번호(1부터)와 한 쪽 개수 |

응답 `data`: `{ auditList, totalElements, totalPages }`. `auditList`의 한 줄

| 필드 | 설명 |
|---|---|
| `seq` | 기록 번호(고유) |
| `crtDtm` | 처리 일시 `YYYY-MM-DD HH:mm:ss` |
| `crtMembNm` | 처리자(사람 또는 기관 이름) |
| `rqstNo` | 의뢰번호 |
| `actnNm` | 작업 이름(의뢰 등록, 상태 변경 등) |
| `bfrStatNm`, `aftStatNm` | 바뀌기 전·후 진행상태 이름(의뢰 등록은 이전 상태가 빈 값) |
| `rsnCnts` | 사유(보완요청·반려·진행취소 사유, "일괄 배정" 등). 없으면 빈 값 |

서버가 지켜야 할 규칙

- 기록은 상태를 바꾸는 모든 API(의뢰·수정·배정·일괄 배정·보완요청·진행취소·진행보류·접수정보 등록·승인·반려)가 같은 트랜잭션에서 남깁니다.
- 기록은 추가만 합니다. 고치거나 지우는 API를 두지 않고, 서버(저장소 권한 포함)가 기록의 수정·삭제를 거절합니다. 화면에서 막는 것만으로는 부족합니다.
- 처리자는 로그인한 회원으로 서버가 정합니다(요청 본문의 값을 믿지 않음). 시각은 서버 시각, 초 단위까지.
- 목업은 진행상태 이력(`statHistList`)만 펼칩니다. 실제 서버는 진행상태 외의 변경(대출실행일·배정 정보 수정 등)도 `actnNm`과 함께 남기면 같은 화면에 그대로 나옵니다.
- 관리자만 조회할 수 있습니다.
