# 데모 모드

백엔드 없이 동작하도록 **데모 모드가 기본으로 켜져 있습니다.**

- **로그인/로그아웃**: API를 호출하지 않고 데모 사용자 정보만 세션에 저장하거나 지웁니다.
- **API 응답**: 공통 axios 인스턴스(`src/services/index.ts`)의 adapter를 목업 어댑터(`src/mocks/adapter.ts`)로 교체합니다. 화면 코드는 실제 모드와 똑같이 동작합니다.
- **목업 데이터**(`src/mocks/data.ts`)
  - 가상 의뢰 24건. 의뢰번호는 `DEMO-00xxxx`, 주소·연락처는 예시 값입니다.
  - 날짜는 **오늘을 기준으로 생성**하므로 언제 실행해도 "오늘 실행 건수" 등이 채워집니다.
  - 데모 중 변경(배정·승인·진행보류 등)은 브라우저 `sessionStorage`에 저장되어 새로고침하거나 사용자 유형을 바꿔도 유지되고, 탭을 닫으면 초기 데이터로 돌아갑니다.
  - 목업이 없는 API는 404로 응답해 기존 오류 처리(토스트) 흐름을 그대로 따릅니다.
- Storybook도 같은 목업 어댑터를 사용하므로, 화면 단위 스토리는 실제 데이터 흐름(TanStack Query → services → 목업 API)으로 렌더링됩니다.

## 오프라인에서 실행

인터넷 없이, 환경 변수(`.env`) 없이도 모든 화면이 데모 데이터로 뜹니다.

```bash
pnpm install
pnpm run dev                     # 또는
pnpm run build && pnpm start     # Storybook은 /storybook
```

| 외부 의존 | 오프라인 처리 |
|---|---|
| 백엔드 API | 데모 모드(기본값)에서 목업 어댑터가 응답하므로 네트워크를 쓰지 않음 |
| 글꼴 Pretendard(예전 jsDelivr CDN) | `pretendard` 패키지(SIL OFL 1.1)의 가변 글꼴 동적 서브셋을 앱 빌드에 포함. Storybook은 `staticDirs`로 `/storybook/fonts/pretendard`에 함께 배포 |
| 주소검색(다음·카카오 우편번호 스크립트 `t1.daumcdn.net`) | 스크립트를 불러오지 못하거나 8초 안에 준비되지 않으면 모달에 예시 주소 목록(`OFFLINE_ADDRESS_SAMPLES`)을 보여 주고 `role="status"`로 "오프라인 예시 주소로 표시 중"을 알림. 고르면 실제 검색 결과와 같은 칸이 채워짐 |
| 분석·오류 수집 | 없음 |

검증은 `e2e/offline.spec.ts`가 합니다. localhost 밖의 요청을 모두 막은 채(route abort) 로그인·금융기관·관리자 모든 화면과 Storybook이 내용과 함께 뜨는지, 외부 요청이 0건인지, 글꼴이 로컬에서 불러와졌는지, 접근성(axe)을 확인하고 주소검색 대체 흐름을 끝까지 따라갑니다.

## 둘러보기

1. 개발 서버를 실행합니다. ([시작하기](../README.md#시작하기) 참고)
2. `https://localhost:4000` 에 접속합니다.
   - 로컬 개발용 자체 서명 인증서라 브라우저에 보안 경고가 뜨면 **고급 → localhost(으)로 이동**을 선택하세요.
3. 로그인 화면에서 사용자 유형을 고르고, 아이디·비밀번호 없이 **로그인** 버튼을 누릅니다.
   - **금융기관**(기본 선택) → 금융기관 홈
   - **관리자** → 관리자 첫 화면(배정관리)
   - **법무대리인** → "준비 중" 안내 (미구현)
   - 이미 로그인한 상태에서 로그인 화면에 들어오면 해당 유형의 첫 화면으로 바로 이동합니다. 다른 유형으로 바꾸려면 먼저 로그아웃하세요.
4. 로그인 화면 아래의 **Storybook 바로 가기** 버튼을 누르면 전환 애니메이션과 함께 컴포넌트 문서(Storybook)로 이동합니다. ([Storybook](storybook.md) 참고)

**금융기관**

| 메뉴 | 확인할 수 있는 내용 |
|---|---|
| 홈 | 오늘 실행·진행중·접수완료 통계, 실시간 등기현황, 공지사항 |
| 의뢰목록 | 미배정 / 배정완료 / 진행보류 / 진행취소 탭, 보완필요 사유 팝업, 전자등기 의뢰(파일 업로드)·수정 |
| 현황조회 | 의뢰번호·진행상태·접수번호·채무자·기간 검색, 등기자료·등기접수증 팝업. 이미지를 누르면 크게 보기(확대·회전·쪽 이동, 키보드 단축키). 지금 검색 조건의 목록을 엑셀(CSV)로 내보내기 |
| 공지사항 | 목록, 긴급 공지 표시, 첨부파일 다운로드 |
| 계정 메뉴 | 비밀번호 변경, 로그아웃 |

**관리자**

| 메뉴 | 확인할 수 있는 내용 |
|---|---|
| 배정관리 | 미배정 / 배정완료 / 진행보류 / 진행취소 탭, 전자등기 신규 등록, 배정(법무대리인 지정)·보완요청·진행취소, 일괄 배정(미배정 건을 골라 법무대리인 한 번에 지정, 배정 정보가 빠진 건은 사유와 함께 실패로 표시), 탭별 목록 엑셀(CSV) 내보내기 |
| 등기관리 | 진행상태별 탭과 건수, 기간 검색, 등기관리 상세(문서·진행 이력), 접수정보 등록, 등기접수증 승인·반려, 목록 엑셀(CSV) 내보내기 |
| 통계 | 기간·단위별 의뢰·접수완료·접수반려·진행취소 건수, 반려율, 평균 처리 일수(목업 진행 이력으로 계산), 표를 엑셀(CSV)로 내보내기 |
| 감사기록 | 누가 언제 어떤 의뢰의 진행상태를 바꿨는지 최근 순으로 조회(기간·의뢰번호·처리자 검색, 의뢰번호는 등기관리 상세로 이동). 데모 중에 바꾼 기록은 시각까지 남음 |
| 회원관리 / 공지관리 | 미구현 ("서비스 준비 중" 안내) |

> 관리자가 처리한 결과(배정, 보완요청, 승인 등)는 금융기관 화면에도 그대로 반영됩니다. 로그아웃 후 다른 유형으로 로그인해 확인해 보세요.
